## 0. 这一份是干什么的

`CONTAINER.md` §5 把选择摆成互斥的两条：

- **(a) 容器是文档**——论文数字保持 Windows 产出，容器供读者复跑；
- **(b) 容器是准绳**——在容器里重跑，**用容器的数字作为论文的数字**。

**作者已选 (b)（2026-09-07）。**

(b) 更相称于一篇以复现审计为核心的论文，但它有真实代价：
**任何一个数动了，论文就得改，而已经读过前一版的评审会看到一份不同的稿子。**
本文件在构建镜像之前把这件事的规则写死，**代价是事先接受的**。

⚠ 本项目纪律 §五-56：§7 是事前预期，写在看任何重算结果之前。

## 1. 为什么必须事前写

论文当前的数产自 **Windows 11 / x86_64-w64-mingw32 / R 参考 BLAS /
`Chinese (Simplified)_China.utf8` 且 `LC_NUMERIC=C`**（`150b_session.txt`）。
容器是 **Linux / OpenBLAS / `C.UTF-8`**。

已知会造成差异的来源，事前列明，**不是事后用来解释某个不合意的数**：

1. **浮点**：BLAS、编译器、libm 实现不同，末位可变；
2. **排序**：locale 不同 → 按字符键排序再取第一行的步骤可能取到别的行；
3. **包解析**：`150a_environment.lock` 锁版本，但 Bioconductor/Posit 快照的
   依赖解析仍可能不同；
4. **Python 补丁版本**：记录为 3.12.4，容器给的是发行版的 3.12.x；
5. **外部二进制**：SMR / PLINK 的 Linux 构建与 Windows 构建。

⚠ **随机性不在此列**：R 与 numpy 的种子化 RNG 跨平台确定。
若种子化结果仍变，那是 **1–3 之一在起作用**，不得记为"随机波动"。

## 2. 接受判据（两层，跑前定死）

### 层一：正文引用的每一个数

判据 = **在正文印出的精度上四舍五入后相同**。
正文印 `4.96`，容器就必须在两位小数上给出 `4.96`。

**执行方式**：容器内重跑分析步骤 → 重跑
`step127_audit_manuscript_numbers.py`。它逐个把正文的数与表对账，
**任何一个 `MISSING` 就是一个动了的数**。同理跑 `step153` / `step154` / `step155`。

⚠ 这正是 `step127` 存在的理由，本文件不另造判据。

### 层二：每一个**判定**（categorical）

以下必须逐字相同，**层二的翻转比层一的位移严重得多**：

- 每个格子的显著/不显著、阴性对照通过/失效、cell void 与否；
- `147a_finemap_decomposition.tsv` 的 `seed_stable`（T/F）与 `verdict`；
- `101b_matched.tsv` 的 `criterion_met`；
- `130c_multilist_verdict.tsv` 的判定列；
- `cqtna` 包 `testthat` 的 271 项断言全过；
- `step101` 自带的 PC（"重现 85.8% / 22.8%"）必须仍然通过。

## 4. ⚠ 全有或全无条款（本文件最要害的一条）

**不得**在容器与 Windows 之间挑选：
一致处采用容器值、不一致处保留 Windows 值——**这是选择性报告**。

只有两种合法终局：

- **容器成为准绳**：所有**可重跑**的数一律采用容器值，
  连同任何翻转了的判定一起采用并报告；
- **容器不作准绳**：全部退回 (a)，`CONTAINER.md` §5 改回 (a) 的措辞，
  并在正文写明退回的理由。

## 5. 数字动了怎么办（迁移规则）

1. 在 `manuscript/NUMBER_MIGRATION_fixed_anchor.md` 里登记：旧值、新值、来源表、步骤；
2. 正文、补充材料、**图注**、`step127` 期望值一并改；
   ⚠ 图注里的数字 `step154` **查不到**，必须手工核（`step127` §1a–1d 才查数）；
3. 重跑四个审计直到全绿；
4. 在 §9 逐条列出**每一个**动过的数——**不得只报"多数一致"**。

## 6. 判定翻转怎么办

**按"翻了"报告，不得静默采用。**

1. 在正文新增或扩写一句，说明该判定在两个环境下不同；
2. 在 §9 记录两个环境各自的值与差异来源（若可判定）；
3. ⚠ **若翻转发生在 `seed_stable` 上**：那不是构建问题，
   而是**关于方法的结果**——S45 的结论应据此加强，
   即该量既依赖种子也依赖环境。

## 7. 事前预期（写在跑之前）

- **绝大多数数不会在正文印出的精度上变**。倍数、计数、两位有效数字的 P 值应当稳定。
- **最可能动的是 `step147`**（susie 纯度按 100 个变异随机抽样估计，
  S45 已记录无种子时 0/1/0 的行为）。**我预期 `seed_stable` 至少有一格翻转。**
- **计数类（位点数、记录数、基因数）应当完全相同**；若不同，
  优先怀疑 §1 第 2 条（locale 排序），而不是浮点。
- **`step101` 的 PC 我预期仍然通过**；若不过，说明浮点差异已大到影响下采样重现，
  那本身是重要发现。
- **`step151` / `step156` / `step158` 应当完全不动**（纯文本、纯列联）。

⚠ **若结果与上述相反**——例如 `step147` 稳定而计数类反而变了——
必须在 §9 写明"§7 未预见"，**不得**事后编一个机制。

## 8. 停止规则与作废条件

- **镜像构建失败或依赖解析与 `150a` 不符** → 记录差异，**先修镜像**，不得带伤重跑；
- **必跑清单第 1–2 项就失败**（审计红或包测试挂） → 判为环境未就绪，
  **不得**继续跑 3–7 并解释单个数字；
- **可重跑覆盖率低于正文所引数字的一半** → 容器不足以作准绳，**退回 (a)**，
  按 §4 的第二种终局处理；
- 重跑只做一次。不得在看到结果后更换镜像基底、包快照或容差。

## 1. 缺陷

第三方复核（Reviewer 1）指出密度匹配置换存在**顺序依赖**：仅反转输入行序，
经验 P 就会改变。我已独立复现（`cqtna` 0.3.0，R 4.4.1，seed 1，10,000 次置换，
melanoma × Soskic_CD4，容差 1.00）：

| 输入行序 | 倍数 | 经验 P |
|---|---:|---:|
| 原序 | 4.951 | 0.0042 |
| 完全反序 | 4.805 | 0.0044 |
| 随机打乱 | 4.856 | 0.0061 |

**这三行应当完全相同——行序不是数据。**

### 1.1 机制（两个，都要修）

```r
sig  <- unique(as.character(mr$locus[mr$fdr < fdr]))   # 首次出现顺序
...
for (L in sig) {
  avail <- setdiff(pool[[L]], drawn)                   # 不放回
  drawn <- c(drawn, avail[sample.int(length(avail), 1L)])
}
```

**(a) RNG 流对齐**。`sig` 的顺序决定了 `sample.int` 的调用次序，
而各位点候选池大小不同，于是**同一条随机数流被切成不同的片段**。
这一项纯粹是假象，**没有任何统计含义**。本例中 0 次抽样耗尽池，
所以观察到的差异几乎全部来自这一项。

**(b) 贪心优先权**。不放回抽样下，**排在前面的位点从更大的池中抽**，
后面的位点池被前面抽走的元素缩小。这是一个真实但小的系统性偏差，
且"谁排在前面"由输入行序这个与数据无关的东西决定。

⚠ 另有一个潜在的第三项：候选池成员顺序来自 `tapply` 的分组排序，
**字符串排序受 locale 影响**。本机 `Chinese (Simplified)_China.utf8` 下未观察到差异，
但跨机器复现时它会变成第三个自由度。一并修掉。

## 2. 修复（在看到修复后的任何数字之前写死）

| # | 改动 | 针对 |
|---|---|---|
| **2.1** | `sig` 与候选池成员一律按**规范顺序**排序（`chr` 数值、`start`、`end`），不再依赖输入行序或 locale | (a)(c) |
| **2.2** | **每一次置换内部，随机化位点的处理次序**。仍为不放回、池耗尽即作废该次抽样（S38 §1.6 不变） | (b) |
| **2.3** | 结果表保存 `n_draws_used`、`n_draws_exhausted`、各池大小（最小/中位/最大）、`min_pool_size`、`effective_draw_fraction` | R2.3 |
| **2.4** | 新增**最低有效抽样比例** `min_draw_fraction = 0.95`：有效抽样少于 95% 即返回 NA 与原因，不出 P | R2.3 |
| **2.5** | 记录 `RNGkind()`、`R.version.string`、`Sys.getlocale("LC_COLLATE")` 到 spec | R2 环境冻结 |

**2.2 为什么是随机化而不是固定某一个次序**：固定次序（哪怕是规范排序）仍然让
某个位点系统性地享有最大池。把次序放进随机化里，贪心偏差在 10,000 次抽样上被平均掉，
**且结果不再依赖任何与数据无关的排列**。

⚠ **这是对实现缺陷的修复，不是对估计目标的改动。**
S38 §1.5（池排除显著位点）、§1.6（不放回、耗尽作废）、§1.7（100% 匹配覆盖率）
**一字未改**。2.4 新增的是一道**更严**的门槛，不是放宽。

## 4. 验收条件

单元测试必须锁死以下三条，否则修复不算完成：

1. **行序不变性**：同一份数据在原序、反序、随机打乱三种输入下，
   `empirical_p` 与 `fold_vs_null` **完全相同**；
2. **重叠池**：构造一组候选池高度重叠的合成数据，验证
   `n_draws_exhausted` 被正确计数，且低于 `min_draw_fraction` 时返回 NA；
3. **诊断字段**：`n_draws_used`、`n_draws_exhausted`、`min_pool_size`、
   `effective_draw_fraction` 全部随结果返回且非 NULL。

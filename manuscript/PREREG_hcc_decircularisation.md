## 0. 先登记：查了什么，以及答案有多少已经可以从来源判定

与 S28 同样的处理——**在写这份预注册之前查看的是来源元数据，不是任何富集结果**。

**已查看**：`84a_hcc_known_loci_grch38.csv` 的 `source` 列、
`hcc/hcc_known_rsids.csv`（GWAS Catalog 拉取结果，**无 study accession 列**）、
GWAS Catalog REST API 返回的「GCST90809296 自身报告的关联」与
「每个候选 rsID 被多少项研究报告」。
**未查看**：任何去循环后的倍数、P 值或位点归属。

### 0.1 循环性的实际范围：73 个已知位点中有 3 个

| rsID | 位置 | 除 GCST90809296 外报告它的研究数 |
|---|---|---|
| **rs4089** | chr4:87,300,193 | **0** |
| **rs7628416** | chr3:126,376,169 | **0** |
| **rs9277534** | chr6:33,087,030 | 不在 GWAS Catalog 中（仅见于该论文 Table 1）|

其余 7 个 `paper_table1` 条目全部有独立支撑，且多数支撑极强
（rs429358 = APOE，1,399 项；rs58542926 = TM6SF2 E167K，1,073 项；
rs738408 = PNPLA3 区，225 项）。

⚠ **`source` 列记录的是"我们从哪里取的"，不是"谁发现的"。**
把全部 10 个 `paper_table1` 条目一律剔除会把 TM6SF2、APOE、PNPLA3 这些
早于结局 GWAS 十年以上的经典位点一并删掉，属于**过度修正**。

### 0.2 一个必须承认的检索限制

`hcc_known_rsids.csv` **没有 study accession 列**，所以**无法**用手上的文件把
"GWAS Catalog 拉取里混进来的 GCST90809296 自身关联"筛出去。
本次改用 API 反查解决：GCST90809296 在 Catalog 中只报告 **8 个** rsID，
全部落在 `paper_table1` 集合内，因此 63 个纯 `gwas_catalog` 条目**不含**该研究的贡献。
**这条限制与其解法一并登记。**

### 0.3 由 0.1 可以事先判定的方向（现在写下）

三个循环位点分别在 **chr4、chr3、chr6**。
HCC 的显著位点在 **chr19 约 19.2 Mb**（TM6SF2 区，ZNF506）与
**chr22 约 43.9 Mb**（PNPLA3 区，SAMM50）。
**三者都不在任何显著位点的 1 Mb 窗口内**，因此：

> **剔除它们不会改变分子（显著位点中有几个是已知的），只会减小分母侧的
> 背景已知位点数，从而使富集倍数持平或略升。**

→ **本次去循环预期不会削弱 HCC 结论，反而可能轻微加强。**
这一点**现在**写下，是为了防止跑完之后把"结论没被削弱"说成一次成功的稳健性检验——
它在设计上就不可能削弱，真正的信息量在于**把循环性的规模量化为 3/73**。

## 1. 为什么黑色素瘤那一侧不做同样处理

melanoma 的已知位点表来自 **Landi et al. 2020**，是一份**与结局 GWAS 不同的出版物**；
结局是 FinnGen R12 + Rashkin 2020 的 meta。参照系不是从结局 GWAS 自身的结果里取的，
因此不存在 HCC 这一类"用同一份 GWAS 定义已知位点"的结构性循环。
⚠ 但**不能声称完全独立**：Landi 2020 与 Rashkin 2020 可能共享部分队列，
这属于样本重叠，与本预注册所处理的循环性是两回事，**须在正文中分开表述**。

## 2. 命题

> **命题 D**：HCC 的位点归属结论不依赖于那些**只有结局 GWAS 自身支持**的已知位点。

## 3. 三种参照系（跑前定死，全部报告，不得只报有利的一种）

| 口径 | 定义 | 位点数 |
|---|---|---|
| **F 全清单** | 现状，与 S20 已发表结果一致 | 73 |
| **★ P 主口径（去循环）** | 剔除除 GCST90809296 外无任何研究报告的位点（rs4089、rs7628416、rs9277534）| 70 |
| **C 保守上界** | 剔除全部 `paper_table1` 条目（**过度修正**，见 §0.1）| 63 |

**主口径是 P。** F 与 C 作为敏感性两端并列报告。

## 4. 主检验

对 **HCC-high（GCST90809296）** 与 **HCC-low（FinnGen R12）** 两格，
在三种口径下各重算：背景已知位点占比、显著位点中的已知数、富集倍数、单侧 Fisher P。
机器与判据与 `step94c` / `step85` **逐位一致**，只换参照名单。

## 5. 判读表（跑之前写死）

| 结果 | 结论 | 正文怎么写 |
|---|---|---|
| **A** P 口径下倍数 > 1 且方向与 F 一致 | **命题 D 成立** | 报告三口径并列；**必须同时写明循环性规模为 3/73，且这三个位点都不在任何显著位点的 1 Mb 内**，因此本检验的结论力有限（§0.3）|
| **B** P 口径下倍数落到 ≤ 1 或方向反转 | **命题 D 不成立** | HCC 泛化**撤回**，并回头检查网格中所有含 HCC 的格子 |
| **C** 连 C 口径（63 位点）都仍 > 1 | 稳健性更强 | 可加一句"即使在过度修正的口径下仍成立" |

⚠ 出现 B 时**不得**改回 F 口径、改窗口、改 FDR 阈值，或只报 HCC-low 不报 HCC-high。

## 6. 这次回答不了的

- **不能**排除 GWAS Catalog 中其他 HCC 研究与 GCST90809296 的**样本重叠**
  （Catalog 不提供队列层面的重叠信息）；本检验处理的是**位点归属的循环**，
  不是样本重叠
- **不能**处理 melanoma 侧 Landi 2020 与 Rashkin 2020 的潜在样本重叠（§1）
- **不改变** HCC 主检验 P = 0.110 未过这一既有结论

### 7.1 主口径与已发表结果**逐位相同**

**P 口径的每一个数字都与 F 口径一模一样。** 原因比"稳健"更平淡：
被剔除的三个位点**连背景都没进**——背景已知位点数在两种口径下都是 31/549 与 32/564，
说明 rs4089、rs7628416、rs9277534 的 1 Mb 窗口内**没有任何工具变量**。
它们既不在分子里，也不在分母里。

### 7.2 判读：A，但这一格的证据力必须按 §0.3 打折

**落在 A**：P 口径下倍数 > 1 且方向与 F 一致，两格皆然。

⚠ **但按 §0.3 事先写下的话，这不构成一次有信息量的稳健性检验。**
三个循环位点在 chr3/chr4/chr6，显著位点在 chr19 与 chr22，
**本检验在设计上就不可能改变结论**。
→ **正文不得写成"去循环后结论依然成立，证明结果稳健"。**
正确表述见 §7.4。

### 7.3 过度修正反而让结果更好看，这一点必须一并报告

C 口径（剔除全部 10 个 `paper_table1`，含 APOE、TM6SF2、PNPLA3）
把倍数从 8.85 抬到 **10.17**、从 17.62 抬到 **20.14**，P 值也随之变小。
机制很简单：剔除已知位点**只减小分母侧的背景已知占比**，分子不动，于是倍数必然上升。

→ **这说明"去循环"这个操作在本设计里天然朝有利方向推**，
因此**不得**把 C 口径当作"最严格检验下依然成立"来引用。
本条现在写下，防止后续引用时误用。

### 7.4 据此定稿的正文表述

> HCC 的已知位点参照系有 73 个位点，其中 10 个取自结局 GWAS 自身的 Table 1。
> 逐个核对 GWAS Catalog 后，其中 **7 个有独立且大量的其他研究支撑**
> （APOE 1,399 项、TM6SF2 1,073 项、PNPLA3 区 225 项），
> **3 个（rs4089、rs7628416、rs9277534）只有该结局 GWAS 支持**。
> 剔除这 3 个后倍数与 P 值**完全不变**（HCC-high 8.85 倍、HCC-low 17.6 倍），
> 因为它们的 1 Mb 窗口内没有任何工具变量，既不进分子也不进分母。
> **因此循环性的规模是 3/73，而这三个位点与本文的显著位点无关；
> 这不是一次能够削弱结论的检验，只是把循环性的规模量化了。**

**必须同时写的限定**：

> GWAS Catalog 不提供队列层面的重叠信息，因此本检验处理的是**位点归属的循环**，
> **不能**排除参照系中其他 HCC 研究与结局 GWAS 之间的**样本重叠**。

### 7.5 一个检索限制，如实登记

`hcc/hcc_known_rsids.csv`（当初的 GWAS Catalog 拉取）**没有 study accession 列**，
无法直接筛掉结局 GWAS 自身的贡献。本次改用 API 反查绕开：
GCST90809296 在 Catalog 中只报告 8 个 rsID，全部落在 `paper_table1` 内，
故 63 个纯 `gwas_catalog` 条目不含其贡献。
**若将来重建该清单，应在拉取时就保留 study accession。**
